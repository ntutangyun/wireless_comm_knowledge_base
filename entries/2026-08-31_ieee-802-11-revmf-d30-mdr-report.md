## Summary (EN)

Over the weekend of 29–30 August 2026, IEEE 802.11 technical editor Edward Au (Huawei) pushed four consecutive revisions (r9, r10, r11 and r12, the last three within fifteen minutes on Sunday afternoon ET) of DCN 11-26-1336, the **Mandatory Draft Review (MDR) report for IEEE P802.11REVmf/D3.0**. The MDR is the formal pre-Standards-Association-ballot editorial audit that the working group runs against the IEEE SA Standards Style Manual and the 802.11 Editorial Style Guide (09/1034), following the process in 11/0615. Eighteen named reviewers from Huawei, Intel, Qualcomm, Cisco, MediaTek, Samsung, Ofinno, Cox, Ruckus/CommScope, InterDigital, HaiLa, Bims Laboratories and Infineon each own one or more style-guide clauses; their findings are compiled into this single document together with the TGmf editor's disposition (Accepted / Revised / Rejected) on each one. The KB previously recorded only that an MDR was being planned (`2026-08-19_ieee-mentor-tgm-digest`); this is the report itself, and it is now readable in full.

Most of the ~250 findings are what an MDR is designed to catch: capitalisation, "0s" instead of "zeros", hanging paragraphs (subclauses that carry both text and child subclauses — 21.3.18, 27.3.1, 27.3.12.5, 27.3.19, 27.3.20.2, 28.9.3.5, 29.10.4, 29.11, 30.3.4 and more each get a new "General" child), abbreviation-expansion order in Clause 3 definitions (a long run of EBCS, EDMG secure ranging, non-NGV and OCB entries all re-ordered so the acronym follows the fully expanded term), and the systematic deletion of "The X element is included in Y frames" opening sentences from roughly twenty element subclauses in Clause 9 (Measurement Report, TPU Buffer Status, Event Request/Report, Diagnostic Request/Report, Location Parameters, Nontransmitted BSSID Capability, SSID List, DMS Request/Response, FMS Descriptor, BSS Max Idle Period, Mesh Channel Switch Parameters, SCS Descriptor, DMG Link Margin, BeamLink Maintenance, MMS, Wide Bandwidth Channel Switch, FTM Parameters, EDMG Specific Parameters, CMMG Link Margin, EDMG Wide Bandwidth Channel Switch), because inclusion rules belong in the usage clause, not the format clause.

The parts that matter beyond editing are in the **ANA (Assigned Numbers Authority) section**, owned by Carol Ansley (Cox). Three of its items are genuine cross-amendment collisions rather than typography. First, `dot11StationConfigEntry` value **249 is already assigned to TGbn in the ANA database and is simultaneously used in the REVmf draft** for `dot11MaxChannelSwitchTimeEnhancedActivated` — introduced through CIDs 24/25 in 11-26-0269r7 without an `<ANA>` placeholder — and ANA resolved it by moving the REVmf attribute to **261**. Second, in Figure 9-177 (subclause 9.4.1.4) the ANA database still marks bits 6 and 7 reserved while the draft carries the Critical Update Flag and the Nontransmitted BSSIDs Critical Update Flag inherited from 802.11be-2024; ANA will update its records to match. Third, bit 9 of the same figure is "QoS" for non-DMG STAs but "Triggered Unscheduled PS" for DMG STAs; the editor rejected the reviewer's change and ANA will instead differentiate DMG from non-DMG in its record. Separately, the reserved range for **Element ID Extension** is corrected from 162–255 to **169–255**, a row for "Element ID Extension 2 present = 254" is added, and reserved ranges are patched in Table 9-226 (values 117–119), Table 9-82 (75–79), Table 9-83 (91, 93–94, 96–101) and Table 9-544 (Public Action value 60 out of order).

## Key technical points (EN)

- **ANA collision, REVmf × TGbn** — `dot11StationConfigEntry` value **249** is assigned to TGbn in the ANA database *and* used by REVmf for `dot11MaxChannelSwitchTimeEnhancedActivated` (a TruthValue control variable enabling enhanced channel switching with the Max Channel Switch Time element). - **Other reserved-range patches** — Table 9-226 (add reserved 117, 118, 119; end range becomes 121–n), Table 9-82 (add reserved 75–79), Table 9-83 (add reserved 91, 93–94, 96–101), Table 9-544 (Public Action field value 60 placed back in order).

## Why it matters / what's new (EN)

Two things make this more than an editorial artifact. The first is the **ANA collision between REVmf and TGbn**. A maintenance revision and an in-flight amendment both reached for MIB slot 249 because a comment-resolution document introduced an attribute without the `<ANA>` placeholder that would have forced a central allocation. That is exactly the failure mode that produces interoperability surprises later, and the record here shows it being caught by an editorial review rather than by an implementer. It is also a concrete illustration of why the REVmf baseline cadence matters to 802.11bn watchers: TGbn's D2.0 text is edited against this rolling baseline, so the two documents share a numbering space and can conflict in it.

The second is the **Element ID Extension range correction and the "Element ID Extension 2 present = 254" row**. The KB has tracked the steady consumption of 802.11 identifier space across `wifi8-uhr` and `mapc-cosr` entries; this MDR makes the current boundary explicit — extension IDs are reserved from 169 upward, and 254 is now formally the escape into a second extension octet. Anyone reading or writing element parsers against D3.0 needs both numbers.

It is also worth recording what this document is *not*: it contains no new mechanism, no performance claim and no normative behaviour change. Its value to the KB is as the authoritative record of where the maintenance baseline stands three weeks before the September interim, and as a first look at how the disposition split runs — the overwhelming majority of findings are "Accepted", a handful are "Revised" with the editor proposing different wording, and only two are outright "Rejected" (the bit-9 QoS naming and one duplicated hanging-paragraph report). Relative to `2026-08-19_ieee-mentor-tgm-digest`, which could only report that an MDR was being planned, this closes the loop with the report itself.

## Why it matters / what's new (ZH)

有两点让这份文档不止是编辑产物。第一是 **REVmf 与 TGbn 之间的 ANA 编号冲突**。一个维护修订版与一个在研修正案同时占用了 MIB 槽位 249，原因是某份意见处理文档引入属性时未标注本应触发集中分配的 `<ANA>` 占位符。这正是日后引发互操作意外的典型故障模式，而这里的记录显示它是被编辑审查而不是被实现者抓到的。它同时具体说明了为何 REVmf 的基线节奏对 802.11bn 观察者重要：TGbn 的 D2.0 文本以这条滚动基线为编辑基准，两者共享同一编号空间，因而可能在其中冲突。

第二是 **Element ID Extension 保留范围的更正与"Element ID Extension 2 present = 254"行**。KB 已在 `wifi8-uhr` 与 `mapc-cosr` 的条目中持续跟踪 802.11 标识符空间的消耗；这份 MDR 把当前边界写明了——扩展 ID 自 169 起保留，254 自此正式成为向第二个扩展字节逃逸的入口。任何针对 D3.0 读写元素解析器的人都需要这两个数字。

同样值得记录的是这份文档"不是"什么：它不含新机制、不含性能主张、不改变规范行为。它对 KB 的价值在于，它是 9 月中期会议前三周维护基线状态的权威记录，也是首次得以观察处置结论的分布——绝大多数为"接受"，少数为"修订"（编辑给出不同措辞），仅两条为"拒绝"（bit 9 的 QoS 命名，以及一条重复上报的悬挂段落）。相对于只能报告"MDR 正在筹划"的 `2026-08-19_ieee-mentor-tgm-digest`，本条目以报告本身闭环。
