## Summary (EN)
Timothy O'Shea, Matthew Pennybacker and Andriy Kharchenko (arXiv v1, 7 Sep 2026; 13 pages, 7 figures, 6 tables — a preview companion to the OCUDU dApp platform release) argue that every published AI-RAN dApp framework to date shares the same structural assumption: a dApp is an external observer that receives an indication and, at most, returns a control message at a later "safe point" — a boundary the paper calls the observer boundary. That design gives crash isolation and language independence, but the paper shows via a 39-use-case audit (spanning neural equalizers, channel estimation, link adaptation, power control, spectrum sensing, interference mapping and CSI prediction) that it structurally cannot express two classes of real workload: inline PHY functions that the slot pipeline cannot progress without (13 of the 39 cases — "Class A"), and bounded real-time MAC/PHY control decisions with hard microsecond deadlines and a conventional fallback (9 cases — "Class B"). Eleven of the 13 Class A rows are flatly inexpressible through an observer boundary, because "an indication carries data outward, and nothing brings a channel estimate, an equalized tensor, or an LLR tensor back into the PUSCH chain of the same slot" — and even before any inference happens, just exporting a 1.47 MB resource grid from device to host costs 73.5 microseconds, with the full round trip costing roughly double that.

The paper's central measurement targets Class B: a 3.2 KB scheduler request (16 candidates, 72-byte intents) sent over six different mechanisms on a single NVIDIA DGX Spark host, first with the system idle and then under the "operationally relevant" condition of an actual OCUDU cell running live on the same host, sharing the GPU. A direct in-process C ABI call holds its P99.9 latency to 5.22 microseconds under load (up from 0.288 microseconds idle) — comfortably inside a 100-microsecond deadline. But paths that cross a process boundary degrade far worse under contention: SCTP loopback's P99.9 tail grows from 15.6 to 181 microseconds (missing the deadline by 81 microseconds), and ZeroMQ's ipc:// transport grows from 21.3 to 787 microseconds (missing by 687 microseconds). The paper traces the cause to the wake mechanism itself — a SEQPACKET control-channel one-way (RTT/2) latency barely moves (3.20 to 3.25 microseconds), but the eventfd-based consumer wake that any cross-process path depends on grows from 99.4 microseconds to 1.62 milliseconds, because the same CPU cores now also carry DU worker threads that enter deep idle states between slots and delay the kernel's wake-up scheduling. The paper's conclusion for Class B is blunt: "a bounded contract is defined by its tail under the load the DU itself creates," and once a request outlives the decision it was made for, "the reply must be discarded on arrival."

Building on these measurements, the paper proposes a three-position "coupling spectrum" rather than a single interface standard: a native/ABI-standard position (in-process C ABI, DU-owned buffers, zero copies, used for Class A and Class B) that trades vendor neutrality for slot-deadline feasibility; a supervised position (a separate worker process on the same host using a shared-memory ring plus SEQPACKET control and CUDA-IPC for GPU payloads, measured at 2.34 microseconds producer cost for 68 KB) for Class C workloads that tolerate some staleness; and a portable position (the standardized E3AP protocol over SCTP with ASN.1/APER encoding, measured at 255 microseconds one-way for a 64 KB indication when idle but 1.57 milliseconds under DU load, and 1.43-1.97 milliseconds for a 734 KB resource grid) for cross-vendor, cross-host, or containerized deployment. A "latest-context cache" mechanism lets Class C observations feed Class B decisions without a message on the decision path at all — a 48-nanosecond acquire versus a 255-microsecond indication round trip. The proposed architecture is validated on a live over-the-air n78 cell (USRP B210, 51 PRB, 30 kHz TDD, three live UEs): a Class A neural equalizer ran in-process on every PUSCH grant across 260,000+ invocations with zero fallbacks at 45-52 microseconds P50; a Class B scheduler intent path validated field-by-field at the boundary in 3.6 microseconds; and an external Python client subscribed over SCTP from outside the DU process, demonstrating that the portable position remains available even while the native position handles the deadline-critical paths.

## Summary (ZH)
Timothy O'Shea、Matthew Pennybacker 与 Andriy Kharchenko（arXiv v1，2026 年 9 月 7 日；13 页，7 幅图，6 张表——作为 OCUDU dApp 平台发布的配套预览论文）指出，迄今为止已发布的所有 AI-RAN dApp 框架都共享同一个结构性假设：dApp 是一个外部观察者，接收一条指示消息，至多在稍后的"安全点"返回一条控制消息——论文将这一分界称为"观察者边界"。该设计提供了崩溃隔离与语言无关性，但论文通过对 39 个用例（涵盖神经均衡器、信道估计、链路自适应、功率控制、频谱感知、干扰地图与 CSI 预测）的审计表明，该边界在结构上无法表达两类真实工作负载：时隙流水线在其完成之前无法继续推进的内联物理层功能（39 个用例中的 13 个，即"A 类"），以及具有硬性微秒级截止时间与常规回退机制的有界实时 MAC/物理层控制决策（9 个用例，即"B 类"）。13 个 A 类用例中有 11 个在观察者边界下完全无法表达，因为"一条指示消息只能将数据向外传递，而没有任何机制能将信道估计、均衡后张量或 LLR 张量带回同一时隙内的 PUSCH 处理链"——甚至在进行任何推理之前，仅将一个 1.47 MB 的资源网格从设备端导出到主机端就需要 73.5 微秒，完整往返的开销大致为此的两倍。

论文的核心测量针对 B 类：在一台 NVIDIA DGX Spark 主机上，通过六种不同机制发送一条 3.2 KB 的调度请求（16 个候选，每个 72 字节意图），先在系统空闲状态下测量，再在"具有运行相关性"的条件下——即同一主机上有一个 OCUDU 小区实际运行、与之共享 GPU——进行测量。直接的进程内 C ABI 调用在负载下将 P99.9 时延保持在 5.22 微秒（空闲时为 0.288 微秒），远在 100 微秒的截止时间之内。但跨进程边界的路径在竞争下的劣化要严重得多：SCTP 环回的 P99.9 尾部时延从 15.6 微秒增至 181 微秒（超出截止时间 81 微秒），ZeroMQ 的 ipc:// 传输从 21.3 微秒增至 787 微秒（超出 687 微秒）。论文将根本原因追溯至唤醒机制本身——SEQPACKET 控制信道单向（往返/2）时延几乎没有变化（3.20 微秒到 3.25 微秒），但任何跨进程路径都依赖的基于 eventfd 的消费者唤醒，却从 99.4 微秒增至 1.62 毫秒，原因是同一批 CPU 核心此时还承载着 DU 工作线程，这些线程在时隙间进入深度空闲状态，从而延迟了内核的唤醒调度。论文对 B 类给出的结论直截了当："一个有界契约由其在 DU 自身产生的负载下的尾部时延所决定"，一旦一条请求存活时间超过其所服务的决策本身，"该回复到达时就必须被丢弃"。

基于这些测量结果，论文提出的不是单一的接口标准，而是一个三位置的"耦合谱系"：原生/ABI 标准位置（进程内 C ABI、DU 自有缓冲区、零拷贝，用于 A 类与 B 类）——以牺牲厂商中立性换取时隙截止时间的可行性；受监督位置（同一主机上的独立工作进程，使用共享内存环形缓冲区加 SEQPACKET 控制通道，GPU 载荷经由 CUDA-IPC 传递，实测 68 KB 数据的生产者端开销为 2.34 微秒）——用于能够容忍一定过时程度的 C 类工作负载；以及可移植位置（基于 SCTP 传输、采用 ASN.1/APER 编码的标准化 E3AP 协议，实测在空闲状态下传输一条 64 KB 指示消息单向耗时 255 微秒，在 DU 负载下升至 1.57 毫秒，传输一个 734 KB 资源网格耗时 1.43–1.97 毫秒）——用于跨厂商、跨主机或容器化部署。一种"最新上下文缓存"机制使 C 类观测结果无需在决策路径上产生任何消息即可反馈至 B 类决策——获取开销仅为 48 纳秒，相比之下一次指示消息往返需要 255 微秒。所提出的架构在一个真实空口运行的 n78 小区（USRP B210，51 个物理资源块，30 kHz TDD，三台真实 UE）上得到验证：一个 A 类神经均衡器在每次 PUSCH 授权时以进程内方式运行，在超过 260,000 次调用中零回退、P50 时延为 45–52 微秒；一个 B 类调度意图路径在边界处逐字段校验，耗时 3.6 微秒；一个外部 Python 客户端通过 SCTP 从 DU 进程之外订阅数据，证明即便原生位置承担了截止时间关键路径，可移植位置依然可用。

## Key technical points (EN)
- 39 audited AI-RAN use cases classified by blocking contract (inline/bounded/nonblocking) and payload residency: Class A (13, resident inline L1 work, e.g. neural equalizers/channel estimation), Class B (9, bounded real-time control with ~100us deadlines, e.g. scheduler/link-adaptation/power control), Class C (17, asynchronous observation, e.g. spectrum sensing/CSI prediction).
- 11 of 13 Class A rows structurally inexpressible through the "observer boundary" every prior dApp framework uses; exporting a 1.47 MB resource grid device-to-host alone costs 73.5 us, full round trip ~2x that, before any inference.
- Class B headline measurement (3.2 KB scheduler request, 6 mechanisms, quiet vs. DU-under-load on one NVIDIA DGX Spark): direct C ABI call 0.288us idle / 5.22us P99.9 under load (meets 100us deadline); SCTP loopback 15.6us idle / 181us under load (misses deadline by 81us); ZeroMQ ipc:// 21.3us idle / 787us under load (misses by 687us).
- Root cause of cross-process degradation: eventfd-based consumer wake grows from 99.4us to 1.62ms under DU load (SEQPACKET control-channel RTT/2 itself barely moves, 3.20 to 3.25us) because shared CPU cores carry DU worker threads that enter deep idle states between slots.
- Proposed 3-position "coupling spectrum": native/ABI (in-process, zero-copy, Class A/B), supervised (same-host worker process, shared-memory ring + SEQPACKET + CUDA-IPC, 2.34us producer cost at 68KB, Class C), portable (E3AP over SCTP/ASN.1-APER, 255us idle / 1.57ms under load for 64KB, 1.43-1.97ms for 734KB grid).
- "Latest-context cache" lets Class C observations feed Class B decisions with a 48ns acquire cost vs. a 255us indication round trip - no message on the decision path.
- Live over-the-air validation (n78, USRP B210, 51 PRB, 30kHz TDD, 3 live UEs): Class A neural equalizer replaces conventional stage on every PUSCH grant, 260,000+ invocations, zero fallbacks, 45-52us P50; Class B scheduler intent validated field-by-field at 3.6us; external Python E3 client subscribes over SCTP from outside the DU process.

## Why it matters / what's new (EN)
The KB's AI-RAN/OCUDU thread has covered the platform's GPU/CUDA PHY implementation (2026-08-07), a two-sided AI-model testbed (2026-08-26), and an E3Controller sidecar for real-time dApp control (2026-09-04), but every prior entry described a working system without quantifying why the underlying interface choices were necessary. This is the first entry to make the "observer boundary" itself the object of study, showing with load-tested numbers exactly which interface mechanisms survive contention with a live DU and by how much (a 687-microsecond deadline miss for a message-queue transport that looks adequate when the host is idle) — turning what earlier entries described as an architecture decision into a measured engineering constraint.
