## Summary (EN)

The O-RAN ALLIANCE's annual security update (published February 24, 2026; ingested now as backfill — the open-ran bin lacked security-spec coverage) documents Working Group 11's release of four major documents through ETSI and ATIS: Security Requirements and Controls Specifications v14.0, Security Protocols Specification v14.0, Security Test Specifications v12.0, and the Threat Management and Risk Assessment Technical Report v8.0. Korea's TTA agreed to adopt the standards, extending their regulatory reach.

WG11's year addressed six operator priorities: mandatory TLS/mTLS 1.3 across O-RAN interfaces, completion of Open Fronthaul security, a security assurance program aligned with GSMA NESAS, Zero Trust Architecture maturation (reaching CISA's "Initial" maturity level, plus a second annual ZTA standardisation workshop), finalised O-Cloud security specifications, and a multi-vendor certificate-management framework built on CMPv2. Forward-looking items put quantum-resistant algorithms and AI security explicitly on the 6G-preparation agenda.

## Why it matters / what's new (EN)

Open RAN's multi-vendor premise is also its attack surface — every disaggregated interface is a trust boundary. This update is the KB's first systematic snapshot of how O-RAN is closing that gap (mandatory mTLS 1.3, fronthaul security, CMPv2 cert management), and the explicit PQC + AI-security 6G agenda parallels the PQC work the IEEE 802.11 TGbt digests track on the Wi-Fi side — the two stacks are converging on the same post-quantum timeline.
