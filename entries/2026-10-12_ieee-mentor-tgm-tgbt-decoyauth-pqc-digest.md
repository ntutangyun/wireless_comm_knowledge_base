## Summary (EN)

Among roughly 25 new base contributions (rev=0) uploaded to IEEE 802.11 Mentor between 2026-09-28 and 2026-10-11, one TGm (REVmf maintenance) thread and one TGbt contribution stand out as new technical proposals rather than routine letter-ballot comment resolution.

DecoyAuth (DCN 11-26-1971r0, Jeff Hansen/Alta Labs, uploaded 2 October 2026, with a companion normative-text changeset DCN 11-26-1982r0 uploaded 7 October 2026) proposes restoring password-only multi-password operation for SAE. The contribution frames this as an 8-year compatibility gap: WFA's 2018 WPA3-Personal launch (built on IEEE 802.11 SAE) did not preserve password-only multi-PSK (MPSK/PPSK) operation that many multi-dwelling-unit (MDU) deployments and installers rely on, and the SAE Password Identifier mechanism that exists today requires sending a cleartext identifier alongside the password -- effectively a username-like selector that existing password-only profiles and clients cannot use unchanged, and whose stable cleartext value the contribution says can link connections across MAC-address randomization. The contribution states this compatibility gap is part of why many installers still choose non-6-GHz APs (where WPA2-PSK remains usable) to retain PPSK/MPSK operation, holding back 6 GHz adoption, where the WFA's 6E certification excludes WPA2-PSK and requires SAE for Personal networks.

DecoyAuth's mechanism lets a station select among multiple configured passwords on one SSID using the password alone, with no identifier or selector crossing the air: the AP encodes fresh SAE response material for each of its configured passwords; the station uses its own password locally to recover the matching response; and the AP checks the SAE confirmation step to identify which credential was used and apply the corresponding policy (VLAN assignment, rate limits, traffic filters), explicitly stated as a design goal to retain SAE's resistance to passive offline password guessing. For larger password sets, the proposal uses Hash-to-Element (H2E) in place of hunting-and-pecking, a fragmented SAE Authentication exchange to carry larger encoded responses, AP-side interpolation-matrix caching, and multi-threaded hashing/candidate preparation. The contribution reports an internal 512-configured-password benchmark on an "AP7-Pro" test platform (September 2026): a cold first connection with AP preparation from scratch took 7 seconds, while a subsequent connection with the matrix cache already warm took 1-2 seconds. Further internal tests report that PMKSA caching, MLO link add/remove, and FT-SAE roaming (observed under 100 ms) all preserve the authenticated credential's identity and VLAN policy across reconnection, link changes, and inter-AP roaming. The proposal defines three AP/network modes -- Disabled (ordinary SAE), Optional (negotiated DecoyAuth alongside legacy SAE access via the primary password for un-upgraded stations), and Required (DecoyAuth enforced) -- intended as a migration path that keeps the existing SSID, passphrases, and credential-to-VLAN assignments unchanged. The companion changeset (1982r0) proposes the concrete normative text: new DecoyAuth Control and DecoyAuth Values information elements, a new SAE_DECOYAUTH_FRAGMENT status code for multi-fragment transport, amendments to the Authentication frame format (9.3.3.11), Status Code (9.4.1.9) and element (9.4.2.1) tables of IEEE Std 802.11-2024, new element subclauses 9.4.2.316/9.4.2.317, and new SAE processing text in 12.4.9 (including fragmented transport in 12.4.9.5); codepoints are left TBD. The contribution's own references point to prior academic framing of the multiple-passwords-in-WPA3 problem (M. Vanhoef, PAKE 2025), and to the DecoyAuth protocol design, Wi-Fi integration specification and research code (github.com/DistriNet/decoyauth), and states that all implemented changes have already been shared on the upstream hostap mailing list. The contribution proposes that TGmf take up the gap as a maintenance-review item.

Separately, TGbt's PQC PTK derivation and SMD contribution (DCN 11-26-1962r0, Jouni Malinen/Qualcomm, uploaded 29 September 2026) proposes updating the Post-Quantum-Cryptography PTK-derivation formula in 12.17.5 to match baseline changes already adopted into 802.11bn/D2.0, independently of the WG-letter-ballot comment-resolution thread that originally touched this clause (DCN 1870r4). The updated derivation (PTK [|| SMD_KDK] = HKDF-Expand(HKDF-Extract(T, EPH_ss || IKM), "Pairwise key expansion" || SPA || AA [|| SMD_Identifier], Length)) carries an optional SMD_Identifier term, included when a non-AP MLD is (re)associating to an SMD-ME, and an optional SMD_KDK output derived only for (re)association to an SMD-ME using the Per-AP MLD PTK mode; the contribution spells out how KCK/KEK/TK/KDK/SMD_KDK bit-lengths compose the total output length.

## Summary (ZH)

在 2026-09-28 至 2026-10-11 期间上传至 IEEE 802.11 Mentor 的约 25 份新基础提案（rev=0）中，TGm（REVmf 维护）方向的一条主线与 TGbt 的一份提案作为新的技术提议脱颖而出，而非常规的信函投票意见处理。

DecoyAuth（DCN 11-26-1971r0，Jeff Hansen / Alta Labs，2026 年 10 月 2 日上传，配套的规范性文本变更集 DCN 11-26-1982r0 于 2026 年 10 月 7 日上传）提议为 SAE 恢复仅凭密码的多密码运行方式。该提案将其定性为一个长达 8 年的兼容性缺口：WFA 于 2018 年推出的基于 IEEE 802.11 SAE 的 WPA3-Personal 并未保留许多多户住宅（MDU）部署与安装商所依赖的、仅凭密码运行的多 PSK（MPSK/PPSK）能力，而当前存在的 SAE 密码标识符机制要求在密码之外以明文形式发送一个标识符——相当于一个类似用户名的选择器，现有仅凭密码运行的配置文件与客户端无法在不改动的情况下使用它，且该提案指出其稳定的明文取值可在 MAC 地址随机化之下仍将多次连接关联起来。该提案指出，这一兼容性缺口是许多安装商仍选择非 6 GHz AP（其上 WPA2-PSK 仍可用）以保留 PPSK/MPSK 运行方式、从而阻碍 6 GHz 频段普及的部分原因，因为 WFA 的 6E 认证排除了 WPA2-PSK，要求个人网络必须使用 SAE。

DecoyAuth 的机制使一个站点可在同一 SSID 下仅凭密码本身在多个已配置密码中进行选择，无需任何标识符或选择器经空口传输：AP 为其每个已配置密码编码新鲜的 SAE 响应材料；站点在本地利用自身密码恢复出匹配的响应；AP 则通过 SAE 确认步骤识别所使用的具体凭据并应用相应策略（VLAN 分配、速率限制、流量过滤），并明确将保持 SAE 对被动离线密码猜测的抗性列为设计目标。针对更大的密码集合，该提案采用哈希到元素（H2E）取代"hunting-and-pecking"方式，使用分片的 SAE 认证交换以承载更大的编码响应，并在 AP 侧采用插值矩阵缓存及多线程哈希/候选准备。该提案报告了在"AP7-Pro"测试平台（2026 年 9 月）上针对 512 个已配置密码的内部基准测试：从零开始准备的冷启动首次连接耗时 7 秒，而矩阵缓存已预热后的后续连接耗时 1-2 秒。进一步的内部测试报告称，PMKSA 缓存、MLO 链路增删以及 FT-SAE 漫游（观测到耗时低于 100 毫秒）均能在重新连接、链路变更及跨 AP 漫游过程中保持已认证凭据的身份与 VLAN 策略。该提案定义了三种 AP/网络模式——禁用（常规 SAE）、可选（已升级站点协商使用 DecoyAuth，未升级的传统站点仍可凭主密码以常规 SAE 接入）以及强制（强制执行 DecoyAuth）——旨在作为一条迁移路径，使现有 SSID、密码短语及凭据-VLAN 对应关系保持不变。配套的变更集（1982r0）提出了具体的规范性文本：新增 DecoyAuth Control 与 DecoyAuth Values 信息元素，新增用于多分片传输的 SAE_DECOYAUTH_FRAGMENT 状态码，并修订 IEEE Std 802.11-2024 的认证帧格式（9.3.3.11）、状态码（9.4.1.9）与元素（9.4.2.1）表格，新增元素子条款 9.4.2.316/9.4.2.317 及第 12.4.9 条 SAE 处理文本（含 12.4.9.5 分片传输）；码点待定。该提案自身引用了此前关于 WPA3 多密码问题的学术研究框架（M. Vanhoef，PAKE 2025），以及 DecoyAuth 协议设计、Wi-Fi 集成规范与研究代码（github.com/DistriNet/decoyauth），并称所有已实现的改动均已在上游 hostap 邮件列表中分享。该提案建议由 TGmf 将此缺口作为一项维护性审查事项予以处理。

另外，TGbt 的 PQC PTK 派生与 SMD 提案（DCN 11-26-1962r0，Jouni Malinen / 高通，2026 年 9 月 29 日上传）提议更新第 12.17.5 条中的后量子密码（PQC）PTK 派生公式，以匹配已采纳进 802.11bn/D2.0 的基线变更，该工作独立于最初触及该条款的工作组信函投票意见处理线程（DCN 1870r4）。更新后的派生公式（PTK [|| SMD_KDK] = HKDF-Expand(HKDF-Extract(T, EPH_ss || IKM), "Pairwise key expansion" || SPA || AA [|| SMD_Identifier], Length)）携带一个可选的 SMD_Identifier 项（当非 AP MLD（重新）关联至 SMD-ME 时包含），以及仅在 Per-AP MLD PTK 模式下（重新）关联至 SMD-ME 时才派生的可选 SMD_KDK 输出；该提案并详细说明了 KCK/KEK/TK/KDK/SMD_KDK 各字段比特长度如何构成总输出长度。

## Why it matters / what's new (EN)

The KB's security-privacy bin has tracked TGbt's PQC/PAKE work and WPA2/3 weaknesses separately, but DecoyAuth is this KB's first record of a contribution proposing to restore password-only multi-password SAE operation, explicitly framed by its author as closing an 8-year compatibility gap opened by WPA3's 2018 launch and cited as a contributing factor in installers avoiding 6 GHz deployments. The contribution cites a public research-code repository (github.com/DistriNet/decoyauth), hostap mailing-list submissions and Alta Labs lab tests as its evidence.
