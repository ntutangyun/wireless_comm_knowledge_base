## Summary (EN)

Day 4 (2026-09-16) of the 2026-09-13/18 Waikoloa interim carried a continuation of the same TGbn LB296 comment-resolution wave, TGbq IMMW PHY baseline wave, and TGbp AMP wave this KB has already digested on 2026-09-14/15/16; those rows are not re-detailed here. Checked against the existing KB coverage before writing anything (per this KB's standing dedupe-assertion / no-unverifiable-firsts discipline), four documents surfaced as genuine first appearances (DCN revision 0) outside those already-covered threads: a first Physical Layer Management Entity (PLME) baseline PDT for TGbq, a TGbt proposal on numbering the recently-introduced Extended Length Element format, an ARC Standing Committee (ARC SC) review of how the term "bridge" is used across the IEEE 802.11 standard, and a TGbp submission proposing draft text for uplink channel access by non-AP ambient-power (AMP) stations. A fifth new-DCN document, "DPWiFi Update Q426" (Carlos Rios, Terabit Wireless, TGbn), was read in full via its downloadable PPTX and confirmed to restate the same 32x32 polarization-MIMO "DPWiFi" proposal already summarised in this KB's 2026-09-14 TGbn digest, here paired with a "Metropolitan WiFi Access" use case -- it is a continuation of that existing thread and is not detailed as a separate item.

## Key technical points (EN)

- **DCN 11-26-1881r0 - TGbq** -- "PDT IMMW PLME". Qisheng Huang and Yanchun Li (ZTE), uploaded 16-Sep-2026; the document itself is dated 2026-09-10. Its abstract states that it contains Proposed Draft Text (PDT) for the IMMW PLME clause of the proposed TGbq amendment, in a version that includes the motions passed up to July 2026. This is the first PDT this KB has recorded that is specifically scoped to the Physical Layer Management Entity (PLME) sublayer for TGbq's Integrated Millimeter Wave (IMMW) baseline, alongside the PHY-procedure and MAC PDTs this KB already covered in the 2026-09-14 TGbq baseline-wave digest (`2026-09-14_ieee-mentor-tgbq-immw-phy-baseline-wave-digest`). [document](https://mentor.ieee.org/802.11/documents?is_dcn=1881&is_year=2026)
- **DCN 11-26-1886r0 - TGbt** -- "Additional info for CID 321". Sigurd Schelstraete (MaxLinear), uploaded 16-Sep-2026. Read in full from the document's own downloadable PPTX. The deck notes that 802.11bt's Extended Length Element format (Clause 9.4.7, Table 9-aa4) so far has one user, the PQC Parameter Element -- which the deck calls "the first element to use the new format" (Extended Length Element ID = 0), and raises the concern that if the format is meant for general future use it needs to be "future-proof" against scenarios such as "legacy" fragmentation as a fallback, alternative encodings for the same element, and other existing Elements later adopting the Extended Length format -- scenarios the deck argues "a separate numbering space for 'regular' Elements and Extended Length Elements may complicate." Its proposed alternative keeps the 2-byte Extended Length Element ID compatible with the existing (Element ID, Element ID Extension) format -- e.g. representing the PQC Parameter Element as (255, 169) rather than a bare 0 -- so that Extended Length Elements can be listed in the standard's main Element ID table (Table 9-16) alongside regular Elements. The deck states explicitly that "this proposal does not modify the Extended Length Element format, parsing rules" -- it addresses only the ID numbering scheme. [document](https://mentor.ieee.org/802.11/documents?is_dcn=1886&is_year=2026)
- **DCN 11-26-1879r0 - ARC SC** -- "Review of the use of the term 'bridge' in IEEE Std 802.11". Joseph Levy (InterDigital), uploaded 16-Sep-2026. Its abstract states that it is a comprehensive review of the term "bridge" as used in IEEE Std P802.11REVmf D3.0, referencing all 73 locations with a suggested action for each, as part of the ARC SC's effort to align IEEE Std 802.11 with IEEE Std 802-2024; the approved suggested changes are to be provided to the maintenance task group (TGmf). [document](https://mentor.ieee.org/802.11/documents?is_dcn=1879&is_year=2026)
- **DCN 11-26-1885r0 - TGbp** -- "TBDs for UL Channel Access". Sanket Kalamkar (Qualcomm Technologies Inc.), uploaded 16-Sep-2026. The document itself is titled "UL Channel Access for Non-AP AMP STA"; its abstract states that it proposes draft text for uplink channel access for non-AP AMP STAs against TGbp D0.5, building on passed TGbp motions covering AP-solicited AMP uplink PPDUs and a slot-based uplink medium-access procedure. The draft text (Clause 39.4) covers slot-based random and scheduled uplink access, selection of the AMP backscatter/operating channel (ABOC), an AMP contention window (ACW), and Number of Slots and Slot Duration fields, with several items left as TBD in the document itself, including ABOC selection on retransmission, whether Number of Slots is present for mono-static backscatter, and the AMP frame content. [document](https://mentor.ieee.org/802.11/documents?is_dcn=1885&is_year=2026)
- Also uploaded 16-Sep-2026, not detailed individually: DCN 1878r0 (TGm, listed as "PHY Review Comments"; the document itself is titled "LB295 PHY Review Comments", Youhan Kim/Qualcomm -- proposed resolutions for ten LB295 PHY comments on P802.11REVmf D3.0); DCN 1877r0 ("DPWiFi Update Q426", Carlos Rios/Terabit Wireless, TGbn) -- read in full via its downloadable PPTX and found to restate the DPWiFi polarization-MIMO proposal already covered in `2026-09-14_ieee-mentor-tgbn-lb296-cr-wave-digest`, paired with a Metropolitan Wi-Fi Access (MWA) use case, an "MWA-12" base-station product line and subscriber and pricing projections that are the contributor's own figures; not detailed as a separate item.

## Key technical points (ZH)

- **DCN 11-26-1881r0 · TGbq** —— "PDT IMMW PLME"。Qisheng Huang、Yanchun Li（中兴通讯），2026-09-16 上传，文档日期为 2026-09-10。其摘要说明该文档为拟议 TGbq 修正案中 IMMW PLME 条款的建议草案文本（PDT），涵盖截至 2026 年 7 月通过的动议。这是本知识库所记录的、首份专门针对 TGbq 集成毫米波（IMMW）基线中物理层管理实体（PLME）子层的 PDT，此前 2026-09-14 的 TGbq 基线浪潮摘要条目（`2026-09-14_ieee-mentor-tgbq-immw-phy-baseline-wave-digest`）已覆盖了 PHY 流程与 MAC 相关的 PDT。[文档链接](https://mentor.ieee.org/802.11/documents?is_dcn=1881&is_year=2026)
- **DCN 11-26-1886r0 · TGbt** —— "关于 CID 321 的补充信息"。Sigurd Schelstraete（MaxLinear），2026-09-16 上传。通过其可下载的 PPTX 全文读取。文稿指出，802.11bt 的 Extended Length Element（扩展长度元素）格式（第 9.4.7 条，表 9-aa4）目前只有一个使用者，即文稿所称"首个使用该新格式的元素" PQC Parameter Element（扩展长度元素 ID = 0），并提出担忧：若该格式意在供未来通用，则需要具备"面向未来"的适应能力，以应对诸如以"传统"分片方式作为后备、同一元素采用替代编码，以及未来其他既有元素采用扩展长度格式等场景——文稿认为，"为'常规'元素与扩展长度元素分设独立编号空间"可能使这些场景的处理复杂化。其提出的替代方案是让 2 字节的扩展长度元素 ID 与现有的（元素 ID，元素 ID 扩展）格式保持兼容——例如将 PQC Parameter Element 表示为 (255, 169) 而非单纯的 0——从而使扩展长度元素能够与常规元素一并列入标准的主元素 ID 表（表 9-16）。文稿明确指出"本提议不改动扩展长度元素的格式与解析规则"——它仅涉及编号方案本身。[文档链接](https://mentor.ieee.org/802.11/documents?is_dcn=1886&is_year=2026)
- **DCN 11-26-1879r0 · ARC SC** —— "对 IEEE 802.11 标准中'bridge'一词使用方式的审查"。Joseph Levy（InterDigital），2026-09-16 上传。其摘要说明该文档全面审查了"bridge"一词在 IEEE Std P802.11REVmf D3.0 中的用法，逐一引用全部 73 处出现位置并给出处理建议，属于 ARC SC 使 IEEE Std 802.11 与 IEEE Std 802-2024 对齐工作的一部分；获批的修改建议将提交维护任务组（TGmf）。[文档链接](https://mentor.ieee.org/802.11/documents?is_dcn=1879&is_year=2026)
- **DCN 11-26-1885r0 · TGbp** —— "上行信道接入待定事项"。Sanket Kalamkar（高通），2026-09-16 上传。文档正文标题为"UL Channel Access for Non-AP AMP STA"；其摘要说明该提案面向 TGbp D0.5，为非 AP AMP 站点的上行信道接入提出草案文本，依据的是任务组已通过的、关于由 AP 征询 AMP 上行 PPDU 以及基于时隙的上行介质接入流程的动议。草案文本（第 39.4 条）涵盖基于时隙的随机接入与调度接入、AMP 反向散射/工作信道（ABOC）的选择、AMP 竞争窗口（ACW）以及"时隙数"和"时隙长度"字段，文档自身仍将若干事项标为待定（TBD），包括重传时的 ABOC 选择、单站反向散射情形下是否携带"时隙数"字段，以及 AMP 帧的内容。[文档链接](https://mentor.ieee.org/802.11/documents?is_dcn=1885&is_year=2026)
- 同日（2026-09-16）另有上传但未逐条详述：DCN 1878r0（TGm，列表标题为"PHY 审查意见"；文档正文标题为"LB295 PHY Review Comments"，Youhan Kim/高通——针对 P802.11REVmf D3.0 上十条 LB295 PHY 意见的处理建议）；DCN 1877r0（《DPWiFi Update Q426》，Carlos Rios/Terabit Wireless，TGbn）——经其可下载 PPTX 全文读取后确认，重述了 `2026-09-14_ieee-mentor-tgbn-lb296-cr-wave-digest` 已覆盖过的 DPWiFi 极化 MIMO 方案，并搭配"都市 Wi-Fi 接入"（MWA）应用场景、一条 "MWA-12" 基站产品线以及用户数与资费预测——这些均为提交者自己的数字；未作为单独条目详述。

## Why it matters / what's new (EN)

The PLME PDT extends TGbq's IMMW baseline coverage in this KB from the PHY-procedure/MAC layer (recorded 2026-09-14) into the management plane. The CID 321 proposal is a concrete follow-on to the Extended Length Element format this KB first covered via TGbt's PQC/PAKE work (`2026-09-11_ieee-mentor-tgbt-pqc-pake-digest`), addressing how that format's numbering should scale once Elements beyond the original PQC Parameter Element start using it. The ARC SC and TGbp items are noted for completeness of this KB's Mentor coverage rather than for introducing a new mechanism.

## Why it matters / what's new (ZH)

PLME PDT 将本知识库对 TGbq IMMW 基线的记录范围从 PHY 流程/MAC 层（2026-09-14 已记录）扩展到了管理面。CID 321 提议是本知识库首先通过 TGbt 的 PQC/PAKE 工作（`2026-09-11_ieee-mentor-tgbt-pqc-pake-digest`）记录的 Extended Length Element 格式的一项具体后续进展，讨论了当 PQC Parameter Element 之外的其他元素开始使用该格式后，其编号方案应如何扩展。ARC SC 与 TGbp 相关条目记录是为了保持本知识库对 Mentor 内容覆盖的完整性，而非因其引入了新机制。
